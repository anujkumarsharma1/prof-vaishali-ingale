### Honest diagnosis of the current design

It is clean and careful, and it looks like a template. Anthropic's `frontend-design` skill lists the exact traits that mark a generated page, and this site shows five of them:

1. Warm cream page, high-contrast serif, terracotta accent (`#fbf4ec` + Fraunces + `#a04a0d`). This is listed as the **number one** AI default.
2. A tracked ALL-CAPS label above the name and above every leadership card.
3. Strings joined with middle dots ("Assistant Professor · Information Technology · AIT Pune").
4. "→" added to link text (Publications →, All news →, section headings).
5. Content cut into identical rounded beige cards with the same shadow (Leadership has seven in a row).

Below the hero, the home page turns into a plain document. Nothing on the 2D site ties back to her actual field.

## 2. Design direction

**Concept: the loss landscape.** Her field is machine learning, and the intro game already rolls a ball down a loss surface to its minimum. The 2D site picks up that idea: fine topographic contour lines (the shape of a loss surface seen from above) become the visual signature. The hero is a live contour field you can push around, and gradient descent becomes the main interaction. Everything else stays quiet so that one idea carries the site.

Why this and not a full rebrand: the watercolour hero art, the 3D room, the OG image, the profile PDF and the print styles are all built on the warm paper palette. Throwing that away costs weeks and breaks the link between the room and the pages. We keep the paper and fix the generic parts.

### Tokens

| Token          | Value                                   | Role                                                         |
| -------------- | --------------------------------------- | ------------------------------------------------------------ |
| paper          | `#fbf4ec`                               | page (unchanged, matches the hero art and the room)          |
| ink            | `#1f1712`                               | text                                                         |
| cinnamon       | `#a04a0d`                               | the single accent: links, the descent dot, active states     |
| contour        | `#a67c52` at 14–35 % opacity            | line work only, never text                                   |
| ink-soft       | `#5e4b3f`                               | secondary text                                               |
| type           | Fraunces (display, opsz animated), Inter (UI and body) | unchanged families, used harder                |

### Rules every agent follows

- One signature moment (the hero field). Everything else is motion that answers what the visitor does: hover, filter, open, navigate. No fade-up on every section.
- Animate only `transform`, `opacity`, `clip-path`, `stroke-dashoffset` and font-variation axes. No layout shift (CLS stays 0).
- `prefers-reduced-motion: reduce` gets a fully static, fully visible page.
- Phones (< 900 px) get lighter versions: no pinning, no sticky stacks, no canvas animation loops beyond a few seconds.
- Canvas and loops pause when off-screen (`IntersectionObserver`) or the tab is hidden (`visibilitychange`). Device pixel ratio capped at 1.5.
- The hero text must never wait for JS. LCP stays the portrait or the name.
- No new CDN dependencies. Vendored GSAP, ScrollTrigger and SplitText are already loaded on every page; use them.
- Never change a fact or a number. Every figure on the site was verified against sources that are not in this repo.
- Do not create `_sass/`, `_scripts/`, `assets/tailwind/` or `tailwind.config.js`.
- Remove the AI-tell chrome: no ALL-CAPS tracked labels, no middle-dot meta strings in new work, no "→" glued onto every link (the single primary CTA may keep one).

## 4. Copy pass ("Editor" agent)

Goal: read like a professional faculty profile, not a generated one. Cut over-explanation, repetition (the same ICNDIA numbers appear on three pages), throat-clearing, and "source:" footnotes that read like an audit log. Keep every fact and figure exactly as it is. The editor owns prose in `_pages/*.md`, `_news/*.md`, `_data/cv.yml`, `_data/timeline.yml`, the labels in `_data/stats.yml` and `_data/pub_topics.yml`, and the `description:` front matter. The editor does **not** touch `_data/room_copy.yml` or `room/js/content.js`: the generator that links them lives outside this repo.

## 5. Agents and phases

File ownership is strict, so parallel agents never edit the same file. Agents do not run git. The lead commits.

**Phase 0 (lead, done before agents start).** Baseline build and screenshots; `tools/portfolio/` harness (`build.sh`, `serve.sh`, `shots.mjs`); new CSS/JS files created and wired into `_includes/head.liquid`.

**Phase 1 (parallel).**

- **Publications:** change 9. Owns `_layouts/bib.liquid`, `assets/js/pubs.js`, `assets/custom/pubs.css`, and the markup (not the prose) of `_pages/publications.md`.

**Phase 2 (parallel, after the Editor finishes, so the copy is final before the markup is restructured).**

- **Home:** changes 1–5. Owns `_layouts/about.liquid`, `assets/custom/home.css`, `assets/js/home.js`, markup of `_pages/about.md`.
- **Sections:** change 8. Owns `_pages/leadership.md`, `_pages/awards.md`, `_includes/milestones.liquid`, `assets/custom/sections.css`, `assets/js/sections.js`.

**Phase 3.**

- **Reviewer** (read-only): desktop and phone screenshots of every page, reduced-motion pass, keyboard pass, contrast checks, console errors, a grep for AI tells, a check that every number still matches the pre-change build, and Prettier. Writes a findings list.
- **Lead:** fixes the findings, re-runs the checks, writes the `portfolio-improvement` skill, commits and pushes.
